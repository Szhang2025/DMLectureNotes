Chapter 1

Overview – Foundations of ML

📌 supervised vs unsupervised · prediction · classification · performance metrics
Key ideas: Supervised learning uses labeled data to make predictions. It includes two main tasks:
  • Prediction of a quantitative variable (regression) – e.g., forecasting sales, delivery time, customer lifetime value.
  • Classification of categorical variables – e.g., churn (yes/no), fraud (fraud/legit), customer segment (premium/basic).
Performance metrics vary by task: for regression, use RMSE, MAE, or R². For classification, use accuracy, precision, recall, F1, or ROC-AUC. Choose metrics that align with business costs and objectives.

1. A retail company wants to predict which customers are likely to churn. This is a:

  • A) Unsupervised clustering task
  • B) Supervised classification task
  • C) Supervised regression task
  • D) Dimensionality reduction task
✅ B) Supervised classification – target is categorical (churn / no churn).

2. A logistics company wants to forecast delivery times (in hours). This is a:

  • A) Classification problem
  • B) Regression problem (quantitative prediction)
  • C) Clustering problem
  • D) Association problem
✅ B) Regression – delivery time is a continuous numeric value.

3. For a fraud detection model, which metric is most critical if false negatives cost $500 and false positives cost $5?

  • A) Accuracy
  • B) Precision
  • C) Recall (Sensitivity)
  • D) R²
✅ C) Recall – we want to catch as many actual frauds as possible (minimize false negatives).

4. Your marketing team wants to segment customers by behavior. No labels exist. Which approach?

  • A) Logistic regression
  • B) kNN
  • C) Clustering (unsupervised)
  • D) Linear regression
✅ C) Clustering is unsupervised – no labels needed.

5. You get 92% train accuracy, 74% test accuracy. What is the issue?

  • A) Underfitting
  • B) Overfitting
  • C) Data leakage
  • D) Insufficient features
✅ B) Overfitting – model memorized training but fails to generalize.

Chapter 2

Multiple Regression

📌 predicting quantitative variables · interpreting coefficients · feature importance
Key ideas: Multiple regression models the relationship between several predictors and a quantitative outcome (e.g., sales, price, demand). Coefficients show the expected change in the outcome per unit change in the predictor, holding others fixed. For regression tasks, use metrics like RMSE (root mean squared error) or MAE (mean absolute error) to evaluate performance – these are more business-interpretable than R² alone. Watch for multicollinearity (highly correlated predictors) which makes coefficients unstable. Prediction intervals provide a range for individual predictions, useful for business planning.

1. Coefficient for sqft is $250. What does this mean?

  • A) Each sqft adds exactly $250
  • B) Holding other variables constant, each sqft adds $250 on average
  • C) Sqft is the only important predictor
  • D) The model is overfitting
✅ B) Holding other variables constant, each extra sqft adds $250.

2. Two predictors have correlation 0.92. What business risk?

  • A) Underfitting
  • B) Coefficients become unstable (multicollinearity)
  • C) Perfect accuracy
  • D) No issue
✅ B) High correlation makes coefficient estimates unstable.

3. Which regression metric tells you the average prediction error in the same units as the outcome?

  • A) R²
  • B) RMSE or MAE
  • C) Adjusted R²
  • D) Coefficient size
✅ B) RMSE and MAE are in the same units as the target variable.

4. A 95% prediction interval is [$120, $180]. How to interpret for business?

  • A) Customer will definitely spend in that range
  • B) 95% confident the true spend falls in this range
  • C) 95% of all customers spend in this range
  • D) Model is useless
✅ B) Prediction interval gives a range for an individual prediction with 95% confidence.

5. Coefficient for "website visits" is 0.02. Business insight?

  • A) Visits have no effect
  • B) Practical impact is tiny – each visit adds only $0.02
  • C) Remove the feature
  • D) Visits are the most important
✅ B) The business impact is tiny; may not be worth tracking.
# Chapter 2: Multiple Regression library(tidyverse) library(caret) set.seed(123) n <- 200 data <- data.frame( sqft = rnorm(n, 2000, 500), bedrooms = sample(2:5, n, replace = TRUE), age = runif(n, 0, 50), price = 100000 + 250 * sqft + 15000 * bedrooms - 500 * age + rnorm(n, 0, 20000) ) train_index <- createDataPartition(data$price, p = 0.7, list = FALSE) train <- data[train_index, ] test <- data[-train_index, ] model <- lm(price ~ ., data = train) summary(model) predictions <- predict(model, test) RMSE <- sqrt(mean((test$price - predictions)^2)) MAE <- mean(abs(test$price - predictions)) cat("RMSE:", RMSE, "\nMAE:", MAE)

Chapter 3

Ridge & Lasso – Regularization

📌 controlling overfitting · L2 (Ridge) · L1 (Lasso) · feature selection
Key ideas: Regularization prevents overfitting by adding a penalty to large coefficients. Ridge (L2) shrinks coefficients toward zero but keeps all features – useful when many predictors matter. Lasso (L1) can set coefficients to exactly zero, performing feature selection – great for simplifying models and reducing data collection costs. Use cross-validation to find the best penalty strength (λ). For regression, RMSE on validation data helps select the best λ.

1. 200 features, 500 rows, high variance. Which method also selects features?

  • A) Ridge (L2)
  • B) Lasso (L1)
  • C) No regularization
  • D) PCA
✅ B) Lasso can shrink coefficients to zero, selecting features.

2. In Ridge, increasing penalty λ has what effect?

  • A) Coefficients become larger
  • B) Coefficients shrink toward zero
  • C) Become negative
  • D) No effect
✅ B) Higher λ pushes coefficients toward zero, reducing variance.

3. Marketing wants a simple model with only top predictors. Which approach?

  • A) Ridge with large λ
  • B) Lasso with cross-validated λ
  • C) Standard OLS
  • D) kNN
✅ B) Lasso selects a subset of features for simplicity.

4. Lasso gives 7 non-zero coefficients out of 30. Business benefit?

  • A) Faster predictions and easier data collection
  • B) Higher R²
  • C) Causal interpretation
  • D) No benefit
✅ A) Sparse model reduces data collection costs and simplifies deployment.

5. Why use cross-validation to choose λ?

  • A) To increase training accuracy
  • B) To find λ that minimizes out-of-sample error (e.g., RMSE)
  • C) To eliminate all features
  • D) To speed up training
✅ B) Cross-validation selects λ that gives best performance on unseen data.
# Chapter 3: Ridge & Lasso Regularization library(tidyverse) library(glmnet) set.seed(123) n <- 200; p <- 50 X <- matrix(rnorm(n * p), n, p) beta <- rnorm(p); beta[20:50] <- 0 y <- X %*% beta + rnorm(n, 0, 2) train_idx <- sample(1:n, 0.7 * n) X_train <- X[train_idx, ]; y_train <- y[train_idx] X_test <- X[-train_idx, ]; y_test <- y[-train_idx] cv_lasso <- cv.glmnet(X_train, y_train, alpha = 1) best_lambda <- cv_lasso$lambda.min cv_ridge <- cv.glmnet(X_train, y_train, alpha = 0) best_lambda_ridge <- cv_ridge$lambda.min lasso_pred <- predict(cv_lasso, newx = X_test, s = best_lambda) ridge_pred <- predict(cv_ridge, newx = X_test, s = best_lambda_ridge) cat("Lasso RMSE:", sqrt(mean((y_test - lasso_pred)^2))) cat("Ridge RMSE:", sqrt(mean((y_test - ridge_pred)^2)))

Chapter 4

Logistic Regression

📌 classification of categorical variables · probability · ROC/AUC · threshold tuning
Key ideas: Logistic regression predicts the probability of a binary categorical outcome (e.g., churn / no churn, fraud / legit). The model outputs log-odds, which are converted to probabilities. For classification, use metrics like accuracy, precision, recall, F1, and ROC-AUC. Choose the classification threshold based on business costs – e.g., lower threshold to catch more fraud (higher recall) at the cost of more false alarms.

1. Model outputs probability 0.35 for default. Threshold 0.5. Classification?

  • A) Will default
  • B) Will not default
  • C) High risk
  • D) Undetermined
✅ B) 0.35 < 0.5 → predicted NOT to default.

2. Fraud model: 90% recall, 60% precision. Which is true?

  • A) Catch 90% of frauds, but 40% of flagged cases are false alarms
  • B) Catch 60% of frauds
  • C) Precision is more important
  • D) Useless
✅ A) Recall = 90% of frauds caught; precision = 60% of flagged are true frauds.

3. Insurance sets low threshold (0.2). What trade-off?

  • A) Lower recall, higher precision
  • B) Higher recall, lower precision (more false alarms)
  • C) No trade-off
  • D) Higher accuracy
✅ B) Lower threshold catches more positives (high recall) but increases false positives.

4. AUC of 0.88 indicates what?

  • A) 88% accuracy
  • B) 88% chance model ranks a random positive higher than a random negative
  • C) 88% precision
  • D) Overfitting
✅ B) AUC = probability that a random positive is ranked higher than a negative.

5. Coefficient for "email open rate" is 2.5. Interpretation?

  • A) For each 1% increase in open rate, log-odds of response increase by 2.5
  • B) Open rate doesn't matter
  • C) Causal
  • D) Each open increases response by 2.5%
✅ A) Logistic coefficients are in log-odds.
# Chapter 4: Logistic Regression library(tidyverse) library(caret) library(pROC) set.seed(123) n <- 500 data <- data.frame( age = runif(n, 18, 70), income = rnorm(n, 50000, 15000), usage = rnorm(n, 100, 30), churn = rbinom(n, 1, plogis(-2 + 0.02 * age - 0.00001 * income - 0.01 * usage)) ) data$churn <- as.factor(data$churn) train_index <- createDataPartition(data$churn, p = 0.7, list = FALSE) train <- data[train_index, ]; test <- data[-train_index, ] model <- glm(churn ~ ., data = train, family = binomial) pred_probs <- predict(model, test, type = "response") pred_class <- ifelse(pred_probs > 0.5, 1, 0) confusionMatrix(as.factor(pred_class), test$churn) roc_obj <- roc(test$churn, pred_probs) auc(roc_obj)

Chapter 5

CART – Decision Trees

📌 both regression & classification · Gini/entropy · pruning · business rules
Key ideas: Decision trees can handle both regression (quantitative prediction) and classification (categorical prediction). Splits are chosen to maximize purity (Gini or entropy for classification; MSE for regression). Pruning removes branches that overfit, making the tree simpler. Trees are great for extracting actionable business rules (e.g., "if income > $75k and age < 30 then high-value customer").

1. Root split: "income > $75k". What does this represent?

  • A) A simple business rule: high vs low income
  • B) The most important feature
  • C) Both A and B
  • D) Overfitting
✅ C) Root split is the most important differentiator and a clear rule.

2. Prune from 50 leaves to 12. Business benefit?

  • A) Simpler, more understandable rules
  • B) Higher training accuracy
  • C) More complex rules
  • D) No benefit
✅ A) Pruning reduces complexity, making tree easier to explain.

3. Leaf: "amount > $500 AND location = international AND time = night". Interpretation?

  • A) Actionable risk pattern for fraud alerts
  • B) Tree is too complicated
  • C) Amount is the only factor
  • D) Location doesn't matter
✅ A) This is an actionable rule for fraud detection.

4. What metric does a classification tree use to decide splits?

  • A) R²
  • B) Gini impurity or entropy
  • C) RMSE
  • D) AUC
✅ B) Gini or entropy measure purity of child nodes.

5. Leaf: 90% churn for "tenure < 12 months AND support_calls > 5". Action?

  • A) Ignore
  • B) Proactively reach out to new customers with many support calls
  • C) Remove tenure
  • D) Use this as the only rule
✅ B) This is a high-risk segment – intervention can reduce churn.
# Chapter 5: CART – Decision Trees library(tidyverse) library(rpart) library(rpart.plot) data(iris) set.seed(123) train_index <- sample(1:nrow(iris), 0.7 * nrow(iris)) train <- iris[train_index, ]; test <- iris[-train_index, ] tree_model <- rpart(Species ~ ., data = train, method = "class", control = rpart.control(cp = 0.01, minsplit = 5)) rpart.plot(tree_model, extra = 1) printcp(tree_model) pruned_tree <- prune(tree_model, cp = 0.02) pred <- predict(pruned_tree, test, type = "class") confusionMatrix(pred, test$Species)

Chapter 6

k-Nearest Neighbors

📌 both regression & classification · distance metrics · choosing k · scaling
Key ideas: kNN predicts based on the "k" most similar training examples. It can be used for both classification (majority vote) and regression (average of neighbors). Distance metrics (e.g., Euclidean) measure similarity. Feature scaling is critical – otherwise features with large ranges dominate. Choosing k is a trade-off: small k overfits, large k smoothes. Performance metrics depend on the task: accuracy/F1 for classification, RMSE/MAE for regression.

1. Using kNN with 100 features. Key preprocessing step?

  • A) Remove all features
  • B) Scale features so large numbers don't dominate
  • C) Use only one feature
  • D) No preprocessing
✅ B) Feature scaling is critical.

2. k=1 gives 100% train, 60% test. What is happening?

  • A) Underfitting
  • B) Overfitting – memorizes training points
  • C) Data leakage
  • D) k is too large
✅ B) k=1 is highly sensitive to noise; increase k.

3. Add "age" (0–100) without scaling. Effect?

  • A) No effect
  • B) Age will dominate distance
  • C) Age ignored
  • D) More accurate
✅ B) Unscaled features with large ranges dominate.

4. Retail uses kNN with 50 attributes. What challenge?

  • A) Curse of dimensionality – distance becomes less meaningful
  • B) Too fast
  • C) No challenge
  • D) Doesn't work with numeric data
✅ A) In high dimensions, all points become far apart.

5. Increase k from 3 to 15. Business impact?

  • A) Predictions become more stable (less sensitive to outliers)
  • B) More erratic
  • C) Training accuracy increases
  • D) No change
✅ A) Larger k smooths decisions.
# Chapter 6: k-Nearest Neighbors library(tidyverse) library(caret) data(iris) set.seed(123) preprocess <- preProcess(iris[, -5], method = c("center", "scale")) iris_scaled <- predict(preprocess, iris) iris_scaled$Species <- iris$Species train_index <- createDataPartition(iris_scaled$Species, p = 0.7, list = FALSE) train <- iris_scaled[train_index, ]; test <- iris_scaled[-train_index, ] knn_model <- train(Species ~ ., data = train, method = "knn", trControl = trainControl(method = "cv", number = 5), tuneGrid = data.frame(k = seq(1, 20, 2))) knn_model$bestTune pred <- predict(knn_model, test) confusionMatrix(pred, test$Species)

Chapter 7

Deep Learning

📌 both regression & classification · layers · dropout · overfitting
Key ideas: Deep learning uses neural networks with multiple layers to learn complex patterns. It can handle both regression and classification tasks. Activation functions (e.g., ReLU) introduce non-linearity. Dropout randomly turns off neurons during training to prevent overfitting. Choose the right loss function (MSE for regression; cross-entropy for classification) and metrics (RMSE/MAE for regression; accuracy/F1 for classification).

  • A) Linear regression

2. 20M parameters, 50k examples. Biggest risk?

  • A) Underfitting
  • B) Overfitting
  • C) Too fast training
  • D) No risk
✅ B) Large models with limited data are prone to overfitting.

3. Dropout rate 0.5. Business benefit?

  • A) Reduces overfitting by randomly dropping neurons

  • A) Always less accurate
  • B) Requires more data and compute; simpler may be sufficient

# Chapter 7: Deep Learning with keras library(tidyverse) library(keras) set.seed(123) n <- 1000 X <- matrix(rnorm(n * 10), n, 10) y <- ifelse(X[,1] + X[,2] + rnorm(n, 0, 0.5) > 0, 1, 0) train_idx <- sample(1:n, 0.7 * n) X_train <- X[train_idx, ]; y_train <- y[train_idx] X_test <- X[-train_idx, ]; y_test <- y[-train_idx] model <- keras_model_sequential() %>% layer_dense(units = 32, activation = "relu", input_shape = 10) %>% layer_dropout(rate = 0.3) %>% layer_dense(units = 16, activation = "relu") %>% layer_dropout(rate = 0.2) %>% layer_dense(units = 1, activation = "sigmoid") model %>% compile(loss = "binary_crossentropy", optimizer = "adam", metrics = "accuracy") history <- model %>% fit(X_train, y_train, epochs = 50, batch_size = 32, validation_split = 0.2, verbose = 0) model %>% evaluate(X_test, y_test)

Clustering

📌 unsupervised · k-means · hierarchical · DBSCAN · silhouette score
Key ideas: Clustering finds natural groups in unlabeled data (unsupervised learning). k-means partitions data into k clusters based on centroids. Hierarchical builds a tree of clusters. DBSCAN finds clusters of arbitrary shape. Use silhouette score to evaluate cluster quality. Inertia measures cluster compactness – lower is better.

4. Logistics clusters delivery zones. Which metric evaluates cluster quality?

  • A) Inertia (within-cluster sum of squares) – lower is better

# Chapter 8: Clustering library(tidyverse) library(cluster) library(factoextra) data <- iris[, -5] set.seed(123) data_scaled <- scale(data) kmeans_result <- kmeans(data_scaled, centers = 3, nstart = 25) fviz_cluster(kmeans_result, data = data_scaled, ellipse.type = "norm", palette = "jco", ggtheme = theme_minimal()) sil <- silhouette(kmeans_result$cluster, dist(data_scaled)) mean(sil[, 3]) hc <- hclust(dist(data_scaled), method = "ward.D2") fviz_dend(hc, k = 3, rect = TRUE)

Ensemble Methods

📌 bagging · boosting · variance/bias reduction · both regression & classification
Key ideas: Ensemble methods combine multiple models to improve performance. Bagging (e.g., Random Forest) reduces variance by averaging many trees – works for both regression and classification. Boosting (e.g., XGBoost) sequentially corrects errors, reducing bias. For regression, use RMSE/MAE; for classification, use accuracy/F1/ROC-AUC. Ensembles are powerful but can be harder to interpret – in business, they often deliver state-of-the-art accuracy for churn, fraud, and demand forecasting.

  • A) AdaBoost
  • B) Random Forest (bagging)
  • C) Gradient Boosting
  • D) Logistic regression
✅ B) Random Forest averages many trees to reduce variance.

2. Highest accuracy for churn model with large dataset. Which ensemble often wins?

  • A) XGBoost (gradient boosting)
  • B) Linear regression
  • C) kNN
  • D) PCA
✅ A) XGBoost is known for high performance.

3. In boosting, each tree focuses on errors of previous trees. What does this mean?

  • A) Reduces both bias and variance
  • B) Always overfits
  • C) Slower but more accurate than bagging
  • D) Both A and C
✅ D) Boosting reduces bias; can be computationally intensive.

4. Retail uses Random Forest with 100 trees. Advantage over single tree?

  • A) More stable predictions – less sensitive to data changes
  • B) Faster
  • C) Simpler to explain
  • D) No advantage
✅ A) Averaging produces more robust predictions.

5. Model is underfitting (high bias). Which ensemble reduces bias?

  • A) Bagging (Random Forest)
  • B) Boosting (e.g., Gradient Boosting)

# Chapter 9: Ensemble Methods library(tidyverse) library(caret) library(randomForest) library(xgboost) data(iris) set.seed(123) train_index <- createDataPartition(iris$Species, p = 0.7, list = FALSE) train <- iris[train_index, ]; test <- iris[-train_index, ] rf_model <- randomForest(Species ~ ., data = train, ntree = 100) rf_pred <- predict(rf_model, test) confusionMatrix(rf_pred, test$Species) xgb_train <- xgb.DMatrix(data = as.matrix(train[, -5]), label = as.numeric(train$Species) - 1) xgb_test <- xgb.DMatrix(data = as.matrix(test[, -5])) xgb_model <- xgboost(data = xgb_train, max_depth = 3, eta = 0.3, nrounds = 50, objective = "multi:softmax", num_class = 3, verbose = 0) xgb_pred <- predict(xgb_model, xgb_test) confusionMatrix(as.factor(xgb_pred + 1), test$Species)

Chapter 10

Support Vector Machines

📌 classification · maximal margin · kernel trick · soft margin (C)
Key ideas: SVM finds the hyperplane that maximizes the margin between classes (classification). Support vectors are the critical points that define the margin. The kernel trick (e.g., RBF) allows non-linear classification by mapping data to higher dimensions. The C parameter controls the trade-off between margin width and misclassification – a business choice between simplicity and accuracy. For classification, use accuracy, precision, recall, or F1 depending on business costs.

1. Data is not linearly separable. Which SVM technique handles this?

  • A) Linear SVM with C=0
  • B) Kernel trick (RBF or polynomial)
  • C) No solution
  • D) Logistic regression
✅ B) Kernels map data to higher dimensions for non-linear separation.

2. Support vectors are the points that:

  • A) Are farthest from the boundary
  • B) Lie closest to the boundary and define the margin
  • C) Are outliers
  • D) Are random
✅ B) Support vectors determine the margin.

3. Increase soft margin parameter C. Business trade-off?

  • A) Lower C = wider margin, more misclassifications
  • B) Higher C = narrower margin, fewer misclassifications, risk of overfitting
  • C) Both A and B
  • D) No effect
✅ C) C controls penalty – a business choice between complexity and accuracy.

4. Bank wants conservative model (fewer false positives – bad loans). How to adjust threshold?

  • A) Lower threshold
  • B) Raise threshold to be more conservative
  • C) No adjustment
  • D) Use regression
✅ B) Higher threshold means fewer approvals, reducing false positives.

5. RBF kernel: what does gamma control?

# Chapter 10: Support Vector Machines library(tidyverse) library(e1071) library(caret) data(iris) set.seed(123) train_index <- createDataPartition(iris$Species, p = 0.7, list = FALSE) train <- iris[train_index, ]; test <- iris[-train_index, ] svm_model <- svm(Species ~ ., data = train, kernel = "radial", cost = 1, gamma = 0.1, probability = TRUE) svm_pred <- predict(svm_model, test) confusionMatrix(svm_pred, test$Species) tune_result <- tune(svm, Species ~ ., data = train, kernel = "radial", ranges = list(cost = c(0.1, 1, 10), gamma = c(0.01, 0.1, 1))) best_model <- tune_result$best.model best_pred <- predict(best_model, test) confusionMatrix(best_pred, test$Species)

Chapter 11

PCA – Principal Component Analysis

📌 dimensionality reduction · explained variance · data compression
Key ideas: PCA reduces the number of features while preserving as much variance as possible. It creates new uncorrelated variables (principal components) that are linear combinations of the original features. Use a scree plot to decide how many components to keep. Explained variance tells us how much information is retained. Principal components are the new features. In business, PCA helps with data compression, visualization, and speeding up other models – but you lose interpretability of original features. It's a preprocessing step, not a predictive model itself.

1. 200 correlated features → 10 PCs explain 85% variance. Business benefit?

  • A) Faster training and less storage
  • B) Perfectly uncorrelated features
  • C) Higher accuracy
  • D) No benefit
✅ A) PCA reduces dimensionality, speeding up downstream tasks.

2. Scree plot: first 3 components explain 70% variance, then flattens. How many to choose?

  • A) 3 – the elbow point
  • B) 200
  • C) 1
  • D) None
✅ A) The elbow is where additional components add little explanatory power.

3. Retail reduces 50 survey questions to 5 components, then clusters. Advantage?

  • A) Easier interpretation – each component captures a theme
  • B) Data becomes non-linear
  • C) Accuracy always improves
  • D) No interpretation
✅ A) PCA components often correspond to underlying business dimensions.

4. Apply PCA without scaling. "Revenue" ($0–$1M) and "age" (0–100). What happens?

  • A) No effect
  • B) Revenue dominates because of its scale
  • C) Age dominates
  • D) Equal importance
✅ B) Scaling is critical; high-variance features dominate.

5. PCA explains 90% variance with 15 components. Use in regression instead of 100 original features. Outcome?

  • A) Simpler, faster training – but lose interpretability of original features
  • B) Accuracy drops to 0%
  • C) Cannot predict
  • D) No change
✅ A) PCA trades interpretability for simplicity and speed.
